# The KMS Ed25519 protocol seam — 2026-09-06

Item 3 of the ranked remainder: the keysources, **3 of 17 files owned** in this area with 108
controls between them. This registers the one authority in it that is a **sealed owner**
rather than a provider adapter.

Baseline: main `af582442` (#825), stacked on #826 / #827 / #828.

## 1. Why this is a theorem and not a registration of three type definitions

The module states its own operational test, and it is R-SEAL's quantifier rather than a
construction-site check:

> delete every length check elsewhere and an over-long signature is still unconstructible

*"This constructor checks X"* quantifies over one site and is silent about the next one added.
*"Every inhabitant satisfies X"* quantifies over the type. Only the second is a theorem, and
this seam is written as the second.

## 2. Three unconstructible wrong values, and one re-verification

| type | what cannot exist |
|---|---|
| `RawEd25519Message` | a pre-hashed input reaching a RAW-only signing call |
| `RawEd25519Signature` | a signature of any length but 64 leaving the seam |
| `Ed25519SpkiDer` | a public key that has not been through RFC 8410 interpretation |

Plus: every signature is verified against **this signer's own advertised
`response_public_key`** before it is emitted, at the seam.

**The pre-hash arm is the subtle one.** `ED25519_PH_SHA_512` / `MessageType: DIGEST` is a
legitimate KMS operation over the very same key. A backend that selects it returns a
perfectly well-formed 64-byte signature that simply does not verify over the raw preimage —
no length check finds it, and the provider returns no error. It is unreachable here because
the type admits no digest arm. And the missing input is **named rather than fabricated**: a
pre-hashed variant arrives as a sibling type when something produces one, and every backend's
`match` then fails to compile until it says what it does with it.

**The mismatched key is the case that survives the other two.** A backend wired to the wrong
KMS key produces a valid Ed25519 signature, of the right length, over the right message —
under the wrong key. Only the re-verification catches it, which is why that check sits at the
seam rather than in each adapter: an adapter that forgets is exactly the case it exists for.
The adapters self-verify too and that is kept as defence in depth, but the property *"every
signature is verified locally before it is emitted"* holds for **any** backend because it
holds here.

## 3. A measured fact about the evidence, recorded rather than smoothed over

M128 weakens the 64-byte interpretation. It names **only**
`only_sixty_four_bytes_make_a_signature` as expected red.

The neighbouring control `wrong_length_signature_fails_closed` drives a backend returning 63
bytes through the **whole signer**. Under a weakening that zero-pads to 64, the padded
all-zero signature is then caught by the seam's re-verification, so that control stays green.
Naming it in `expect_red` would have been a false claim about what the probe proved.

**The double defence is a fact about the design, not a gap** — and it is exactly why the
probe is worth having: without it, one would read the two controls as two independent pieces
of evidence for the length rule, and only one of them is.

## 5. Named rather than absorbed

**`remote_signer_call/`** — three files, ten controls — decides whether a failed signer call
means *the account is out of quota* or *this request was bad*. That answer arms the
handshake-path throttle, and getting it wrong is a live failure in both directions: a missed
throttle is a handshake flood against an already-throttled signer, and a spurious one refuses
handshakes on a healthy signer. It belongs to no unit.

It is **not** registered here, and the reason is lane identity. It is gated
`#[cfg(any(feature = "aws_kms_keysource", feature = "gcp_kms_keysource"))]` — the shape
ADR-MCPRE-061 records as the trap, because a unit naming ONE feature measures the module under
that one and says nothing about the other. It needs a slice that measures both lanes, and
folding it in under one feature would have produced exactly the "green that measured nothing"
this project has repaired three times.

## 6. What remains in this area

`gcp_kms_keysource.rs` (2 660 lines, 39 controls), `aws_kms_keysource.rs` (1 181, 14),
`aws_sts.rs` (1 507, 26) and `pkcs11_keysource/` (6 files, 9 controls) stay unowned. They are
the adapters beneath this seam, and each is its own slice — the theorem's scope says in terms
that nothing here establishes that any of them speaks its provider's protocol correctly,
selects the right key, or reaches the endpoint a deployment intended.
